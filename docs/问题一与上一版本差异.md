# 第一问与上一版本的差异说明

## 比较基线与数值口径

“上一版本”采用本目录独立 Git 仓库中唯一可追溯提交 `1c7b1c5`（提交信息为 *Add latest problem 1 solver and datasets*，提交时间 **2026-09-24 22:56:26 +08:00**）的交付物。该提交中的 `final_results/final_average_speedup.csv` 给出五核均值 **4.031050361×**，提交内的 `final_results/reports/优化结果说明.md` 也把 4.031×定义为当时最终的五核结果。因此它是目前最可证的“上一版本”基线；仓库没有更早的提交可用于进一步追溯。

当前工作区的最终表位于 `results/final/`，尚未提交到上述 Git 历史。其 `final_average_speedup.csv` 给出五核均值 **4.079865198×**（展示时为 4.080×）。两组数均以 100 个用例逐例计算

\[
\text{speedup}_{i,k}=\frac{T_{i,1}}{T_{i,k}},\qquad
\overline{\text{speedup}}_k=\frac{1}{100}\sum_{i=1}^{100}\text{speedup}_{i,k},
\]

而不是以总 makespan 的比值替代逐例平均。当前表共有 1～5 核各 100 条有效评分，共 500 个配置；单核基准固定。

历史报告还记录了同一轮内部的阶段数：3.580×、3.616×、4.018×和 4.031×。它们用于解释旧版自适应聚类和重排的收益，**不应**与当前最终 FM 结果 4.079865×混为同一个阶段。`算法文献与建模说明.md` 中的 4.077066 是另一份叙述材料记录的历史迭代值，也不是当前最终 CSV 的精确口径。

## 优化带来的变化

当前最终五核结果相对上一版提高 0.048814837×。这项提高应归因于“以已有计划为 incumbent 的无环 FM 边界细化、少量安全收缩、重新列表调度，以及只接受官方评分更优的候选”这一组合，而不能从现有材料中拆分出每个 FM 子机制各自的精确贡献：`results/final/reports/ablation.csv` 是旧版 `refine_partition_schedule.py` 阶段的逐例消融表，记录到 4.031 历史阶段，未提供当前 FM 与未使用 FM 的同口径全量对照。

有证据支持的改善范围如下。

| 层次 | 可证变化 |
| --- | --- |
| 旧版构造阶段 | 旧报告显示，固定切图的观测时长重排使均值从 3.580×到 3.616×；通信和并行度共同驱动的自适应切图到 4.018×；搬运反馈和重排到 4.031×。这些是旧版内部阶段，并非当前 FM 的消融。 |
| 当前最终阶段 | 当前 `results/final/final_results_100cases.csv` 中五核 `method` 标记为 `fm_5core_latest`，最终均值为 4.079865198×。逐例核查应将它与上一版提交中的 `final_results/final_results_100cases.csv` 对应行比较。 |
| 结果解释边界 | 改善以各用例的正式 makespan 为准；额外搬运量仅在 makespan 相等时用于择优。因此不能据此宣称总搬运量必然下降，也不能把平均 4.080×解读为每个用例都达到 4×。 |

## 仍未解决的局限

1. **代理与真实执行仍有差距。** 共享 DDR 争用、缓存峰值、任务重叠和等待传播受具体执行顺序影响；当前目标中的边界字节与最大流水线负载无法精确复现官方 makespan。最终仍必须依赖评测器筛选。
2. **存储项未作为目标评分项。** runner 传入的 `cfg['capacity']` 是含 `L1`、`UB` 等键的字典，而 `Hypergraph` 只读取 `cache_capacity_bytes`，故当前运行中的 `memory_limit` 为 `None`、`memory_penalty` 为 0。`AcyclicFM.memory_weight` 也未进入目标公式；`pressure` 仅按跨组张量累计，并用于 `_active()` 选择 active set 的优先级。不能把实现描述为完成了存储压力或可调内存权重优化。
3. **不是完整的多层算法。** 当前仅在有限候选中做一次浅层安全合并及 FM 细化，没有粗化—初始划分—逐层展开—每层细化的完整多层流程。
4. **搜索覆盖有限。** 单个划分最多形成有限计划，合法且未超时的候选才会被评分；因此当前结果是可复核的局部改进，不能证明全局最优。
5. **当前 FM 的严格消融缺失。** 可用的 `ablation.csv` 支持 4.031 以前的自适应聚类阶段解释，但没有“当前 FM 开/关、相同候选预算、全 100 例”的对照实验，不能量化 FM 对 0.048814837×增益的单独因果贡献。

## 算法思想的文献依据

下列文献只用于说明所借鉴的算法思想，并不表示当前代码完整实现了论文算法。

| 文献 | 支持的思想 | 当前实现的对应与差距 |
| --- | --- | --- |
| Fiduccia、Mattheyses, [A Linear-Time Heuristic for Improving Network Partitions](https://limsk.ece.gatech.edu/book/papers/fm.pdf), DAC 1982 | 通过移动收益、锁定移动和保留最佳前缀细化划分。 | `acyclic_fm_refinement.py` 采用边界移动、锁定和最佳前缀回退；每次重算代理目标，未实现论文的线性时间增量收益更新。 |
| Popp 等, [Multilevel Acyclic Hypergraph Partitioning](https://arxiv.org/abs/2002.02962), 2020 | 用有向超图表达一对多依赖，在无环约束下结合粗化和细化。 | 张量超边和商图无环检查与该问题形式相符；当前只有浅层收缩，并非论文的完整多层流程。 |
| Moreira、Popp、Schulz, [Graph Partitioning with Acyclicity Constraints](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.SEA.2017.30), SEA 2017 | 将商图无环作为划分可行性约束。 | 当前在每次 FM 移动及候选合并后检查任务商图无环；本题另含核调度与硬件资源约束。 |
| Papp 等, [Efficient Multi-Processor Scheduling in Increasingly Realistic Models](https://arxiv.org/abs/2404.15246), SPAA 2024 | DAG 调度中显式考虑通信、同步与机器层次结构。 | 当前列表调度和代理项考虑通信及同步；机器模型、共享 DDR 与缓存建模均未等同于该论文。 |
